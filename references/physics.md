
# 新建物理与排错

## 从一条链开始

MHWI 的装备物理包括 MOD3 骨架与权重、CTC 骨链，以及需要时的 CCL 身体碰撞。优先选同一装备槽里在游戏中已经表现出动态的路径。在当前静态资产副本上留一个小试件，先验证单链，从最容易观察的尾巴或侧摆开始，再添加其他部位。

1. 用 [制作与验证](build.md) 中的 `layout` 确认 rig、网格和遮罩组。查看该槽所有原生骨号，以及已生效的 CTC、其他会同时加载的装备部件、头发和脸。选当前 rig 与共载资产未使用的功能 ID，并记录哪些编号需保留。MOD3 remap 空间为 0–511，单模型骨数上限 255，超过旧项目常用范围需独立实机确认。避免把另一条已存在的链当作空闲编号。
2. 用 Blender 休息姿态的世界坐标定节点。起点贴近真实固定点，父骨选择随固定点运动的主骨。每个链按实际布料垂向或弯曲中心线布 3–8 段内可控的节点。节点尽量经过衣料中部，末端稍收回。长衣料弯曲时沿中线逐段布点。根据布料层厚和动作需求再增加分段。
3. 在 Blender Weight Paint 画辅助组，如 `SIM_TAIL`、`SIM_FRONT`、`SIM_SLEEVE_L`。每组只覆盖该链的衣料、挂件或相应边缘。贴根沿主骨走，远端向相邻两动态骨渐变。左右分开，衬里、滚边、小挂件需要与主体跟随时共享同链且彼此对齐。选择过大的物理区域会带动皮肤、手或另一片裙摆。
4. 写 [配置](../examples/build.json) 后运行 Blender `build`。每条链记录显式 ID、父骨 `anchor`、依序排列的 `points`、要绑定的 mesh／mask、节点参数；同一顶点只能用一条脚本生成的链。如需跨链混合，在 Blender 手动控制权重，并重新核对离线变形。
5. 启用碰撞前先确认无碰撞的链能动。胶囊默认沿两根锚骨的静置位置放置。可在骨骼局部的游戏坐标系内填写端点偏移，单位厘米。半径应贴近实际身体且考虑骨链节点半径。检查静置布料到胶囊线段的距离减两者半径之和，避免出生即被顶起。贴腿裙摆先试骨盆和大腿的少量胶囊，缓慢增加，不要同时把半径、弹性和重力大幅调高。
6. 检查导出后的日志、同 stem 文件和装到游戏后的表现。需要时在 Blender Pose Mode 只旋转动态骨检查裙袖网格是否跟随，这能验证蒙皮。真实摇摆、静置漂移与碰撞仍以游戏动作验证。

## 部件取舍

| 部件 | 固定点 | 节点与权重 | 第一个验证动作 |
|---|---|---|---|
| 尾巴 | 尾根附近的骨盆或经验证的尾根锚骨 | 沿自然弯曲中心线，根部逐渐离开骨盆权重。外层毛和多片尾尖尽量同相 | 起跑、急停和快速转身 |
| 裙摆前片 | 腰带对应的骨盆／腰部锚点 | 按片从上到下走。跨腿的前片需从一侧借权重时先验证蹲姿，避免被左右腿拉成楔形 | 跨大步、下蹲，观察腿间与布片 |
| 侧裙与后裙 | 各片在腰带实际连接处 | 左右独立，必要时按前后片再分。长外层和有横向支撑的短层分别看 | 抬腿、转身和跑步停下 |
| 垂袖 | 袖口实际固定的上臂或前臂 | 左右独立，紧贴手臂的段由手臂驱动，脱离的垂布才加动态 | 举臂、握武器、放下手臂 |

## 配置及常用数值

- `points`、`radial` 等坐标使用 Blender 世界米，在标准 MHWI 导入方向下 Blender `(x,y,z)` 对应游戏 `(100x,100z,-100y)` 厘米。`root_fade_segments` 以节点间段为单位，`[0,1.25]` 要求至少三节点。两节点链使用如 `[0,0.9]`。
- `strength` 是遮罩的最大动态份额。修改原体骨权重时按剩余比例保留。`max_influences` 默认四，确认合适的 MOD3 块后才用八。主骨过多挤掉微弱物理权重时，简化源皮权重并重查关节。
- 起试参数可用阻尼 0.10–0.18、传递 0.25–0.35、弹簧 0.01–0.03、风 0.08–0.20；布料的重力、质量、角度和半径要与尺寸与既有参考链对照。脚本默认重力输入 240，写到游戏 Y 轴负向。适当增加阻尼可减少停步后的多余摆动。防止完全贴死时先确认骨轴、权重与限制角。
- `collision` 取 0（关闭）、4（与模型碰撞）或 6（模型和自碰撞）。先做 0 再做 4 对照，有明确自碰撞需求时再试 6。`colliders` 提供胶囊 `start_id/end_id`、`start_cm/end_cm` 和 `radius_cm`。
- 对已验收的尾链等，导入其同 stem MOD3 后用 `base_ctc`、`base_ccl` 保留原文件记录，再附加新链。脚本保留旧 CTC 全局参数、链和节点字节以及已有 CCL 记录，只更新表计数。原有物理需要的 MOD3 骨与权重由导入的基线保留。需要修改旧链本身时，在插件 UI 专门编辑旧文件，并检查原导入有没有滤去未知骨或短链。

## 由证据定位问题

1. **全无动静。** 核对实际装备号、槽和文件路径。比对安装目录与 ZIP 或改号后包，同 stem 的 MOD3、CTC 和 CCL 要一起到达。检查文件名大小写、缺失和旧包覆盖。先确定游戏确实读到当前 MOD3。
2. **部分链能动。** 能动的链把排查范围缩到未动部件。用 `audit --check-mrl` 比较该槽 CTC 节点、MOD3 remap 和加权点数。看静态实拍中本应动的具体面到底归哪一个 MOD3、哪一个子网格。如果权重只是手臂／髋等体骨，先补同模型物理权重。若链与网格分在两槽，先验证是否能把该部件合并到已知能动的槽，再独立试原槽。迁移前比较两套骨的名字、层级和静置矩阵，以及 UV、材质、LOD 和装配可见性。
3. **只抖、扭曲或永久甩偏。** 先看链父骨、局部布点与 CTC 初始轴方向，检查根部是否实心绑定。再区分点半径过大、衣料静置与胶囊交叠、重力过强、传递过强、角度过窄及左右组混涂。先禁用碰撞，验证动静，再逐个恢复胶囊。
4. **穿腿或袖子飘出。** 验证卸碰撞和启碰撞两次，对明显穿插做大幅单变量对照，确认碰撞是否实际生效。修正裙片左右受体、根到末端权重和过大的角度，再细调胶囊。裙片边角长期穿入时补校节点覆盖或移动轴线。
5. **打包前重复诊断。** 核对 CTC chain/node 表、同 stem MOD3 remap、每条链至少一个远端有正权重、CCL 端点存在、不会因改号漏装。离线通过仅说明可继续实机验收。

## 二进制读回

CTC v28 长度为 `80 + 80×链数 + 112×节点数`，头内链数、节点数是字节 16、20 处的无符号 32 位值。节点功能 ID 是节点 +72 处的小端 u16，半径、角度、宽度、质量、弹性在 +80…+96。节点矩阵的行口径按参考插件版本核对，脚本把游戏 X 轴旋转到下一段方向后转置写入。CCL 头长 16，每胶囊记录长 64，起止 ID 在记录 +4/+6。用引擎回放确认参数和坐标实际效果。[CTC/CCL 模板](https://github.com/chikichikibangbang/MHW_CTC-CCL_010Template)
