
# 外观移植案例复盘

案例来自一次用 MMD 素材制作可改号猎人外观的本地练习。下文保留可迁移的方法和失败信号，接手者根据新角色重新选择骨架、编号和阈值。

| 遇到的证据 | 做出的判断和处理 | 供下一位代理采用的准则 |
|---|---|---|
| 初选素材的使用范围与跨游戏试作不吻合，另有注明学习交流用途的备选。先前工程也保留了不稳定的结构。 | 用备选模型重新建立静态与装配基线。本地失败件用来复盘，参考成品用于查结构和外观。 | 先查作者声明与本次使用范围。成品里能验证的一项技术经验可作为对照，具体模型、贴图、参数与装配需要从当前素材决定。 |
| 目标是让使用者用常见工具改装备编号。原壳形状与角色轮廓不同。 | 以游戏同类骨架和文件约定为接口，几何按角色体态制作。覆盖五个槽，共用独立路径下的纹理。 | 先在一个便于测试的编号上验证。把原壳当骨骼和路径参考。改号只涉及装备命名树与同 stem 文件，纹理命名空间尽量独立。 |
| 首张实机反馈显示站姿轮廓不自然，同时尾巴已有运动，裙摆与袖子看起来僵硬。 | 把体态和物理拆成两个可独立比对的变量。身体检查优先沿肩肘腕重建轮廓并看骨盆附近的跨步拉伸。物理首先对照真正能加载的尾链路径。 | 单张姿势有透视、装备遮挡和角色动作。用原素材、同视角休息姿势及几个姿态交叉确认。既有能动的链是目录和文件加载的正对照。 |
| 旧版有腰部 CTC 文件；检查前裙摆网格时看到了分件，实际远端却缺少动态影响。仅检查文件存在会漏掉这个问题。 | 跟到同一个 MOD3、bone remap 和逐网格权重，补前片、侧片和左右垂袖的功能骨与权重。参考实机已经能带动尾巴的 body 路径，将本项目的动态网格和链集中到该部件，保留其他槽所需的覆盖。 | 部件归属要以导出后的 mesh 为准。若两槽骨架不同，先对齐实际使用骨的头、父链和 rest 矩阵再迁移。其他 MOD 的 wst 等槽仍可用，先做一个最小实机探针。 |
| 即使节点 ID 存在，衣料也可能绑错。弯尾直线一投影，远处容易吸到不相邻的段。把前裙按全身最近骨处理也会混到左右腿。 | 腰带或袖口近根保留主骨；每片布、左右袖和尾巴沿各自中心线布点，给明确区域设权重并用端部正权重读回。弯尾按段投影。 | 自动权重可以是初稿。用孤立节点姿势亲眼确认哪个面会动，配件应和衣料同相。按表核对 CTC ID、网格参与点数、根与末端梯度。 |
| 动态路径可加载仍可能穿腿、过度甩动或袖口顶起。 | 先确定链会动，再测试 CCL。对比碰撞关闭／开启时动作，胶囊位置参考骨盆和腿，参数用小步骤调整。 | CTC 角度、风和弹性调试需要稳定对照。先减少变量，再区分碰撞未生效、静置重叠与过大的范围。离线参数和浏览器截图无法证明实际帧序列。 |
| 第二张游戏图反馈小臂偏细显手大，其他部分基本满意。 | 选择加厚肘腕之间的皮肤，渐变至肘和腕，手掌和握点沿用。最终补丁只动一个皮肤子网格内 565 个顶点，最大位移约 3.62 mm。通过局部形状、同姿势袖面交集和数据差异检查影响范围。 | 用户已认可的部分优先冻结。先定义改动边界，再选择改网格、骨或权重。对已验收物理和装配，只修局部截面时优先保留原数据，数值由当前模型决定。 |
| 清理时存在多份旧 ZIP 和一份同目录的离线检视工程。 | 以用户选定的包为基准核对名称和哈希，将其余三份可明确识别的旧 ZIP 放回收站，保留工程与源素材。 | 只处置明确淘汰的产物。参考和输入放在各自目录，继续使用版本化工作副本。 |

## 记录模板

每次修订记录四项即可。写下观察到的问题、支持判断的证据、最小的改动以及确认条件。比如“袖子转身完全不动 → arm 网格的垂布没有新骨权重，body 尾链可加载 → 给左右垂布分别建链并与加权网格配对 → 蒙皮孤立姿态验证，再进游戏跑停实测”。若结论依赖猜测，记下注定能推翻它的短对照。

## 本技能的本机验证

- Blender 4.3.2 已验证从独立工作目录加载脚本、导入 FBX 和捐赠 MOD3、建立配置、权重重绑、小范围增厚、创建 CTC／CCL、保留并追加旧物理，以及重新读回导出。追加用例的旧链、节点与胶囊记录保持逐字节一致。
- 用项目采纳包的副本读取了五件 MOD3 与匹配材质，检查了 13 张自有纹理。13 张 TEX 经 DDS 往返保持字节一致，五份 MRL3 的路径和材质哈希重写通过，重新打包的 26 个条目内容与原包一致。
- 用另一份测试副本验证定长体态补丁，确认变化局限于目标皮肤子网格的位置、法切线和相应骨包围记录。测试配置是局部回归探针，实际新项目要重新测量截面。
- 以上是工具与文件的离线验证。PMX 入口依赖本机 MMD Tools，换版本前做一次导入探针。新增链的实机幅度、碰撞和动作表现由新项目单独验收。
